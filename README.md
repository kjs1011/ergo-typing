# 자료 입력 자세 실험

[노트북 실험](https://kjs1011.github.io/ergo-typing/) / [태블릿 원본](https://kjs1011.github.io/ergo-typing/tablet.html)

## 사진·영상 관찰 추가

측정법 선택 메뉴 대신 실험 순서에 따라 촬영과 측정을 안내한다. 관찰 규칙은 **버전 2**이며 기존 입력 과업 규칙 버전 6과 별도로 기록한다. [주제 적합성·10쪽 구성](https://kjs1011.github.io/ergo-typing/study-plan.html)에서 수업 자료와 연결한 판단과 분석 계획을 볼 수 있다.

1. 연습 직후, 휴대폰을 옆에 고정하고 눈높이의 정면 표적을 편하게 보는 기준 사진 1장 또는 3~5초 영상을 남긴다. 머리·팔·손목·발 지지가 보이는지 예비 촬영으로 확인한다. 가능하면 전면 보조 영상을 같은 시각에 촬영한다. 전면 영상만으로 앞뒤 숙임각이나 좌우 회전각을 정확한 도수로 입력하지 않는다.
2. A·B 각 배치의 두 번째 시행을 촬영한다. 세 번째 시행 준비 화면에서 녹화를 멈추도록 안내한다. 입력 시작 전 3초 카운트다운, 시작 안내음 1번, 종료 안내음 2번으로 분석 구간을 구분한다.
3. 기본 입력 결과를 전송한 뒤 관찰 기록지를 연다. 핵심은 각 조건 두 번째 시행의 10~90% 아홉 시점에서 행동(입력·비입력·혼합·구분 불가)과 자세(중립·숙임·회전·동시 발생·판독 불가)를 기록하고, 행동별 대표 장면을 RULA로 평가하는 것이다. 비입력에는 탐색·대조·대기가 섞이므로 원본 읽기와 동일하게 해석하지 않는다.
4. 각 행동의 최빈 머리 자세 범주에서 가장 이른 장면을 선정한다. 동률은 먼저 나온 범주를 선택한다. 해당 장면에서 수업 17쪽 또는 Cornell 평가표의 신체 각 부위·근육 사용·힘/하중을 평가하고 표 A·B·C로 최종점수를 구한다. 사이트에는 최종점수와 보정 후 목·몸통·손목 점수, 평가 측과 평가자 코드, 선택적 독립 재평가 점수를 입력한다. 필수 부위가 안 보이면 평가 불가와 사유를 남긴다. 선정 장면이 바뀌면 점수를 다시 입력한다. 다른 시행의 신체 부위를 섞어 한 점수를 만들지 않는다.
5. 보조 자료로 기준 각도와 시행의 25%·50%·75% 시점 각도, 영상 전체의 관찰상 숙임 구간 수·합계 시간을 직접 입력한다. 모든 시점은 실제 수행시간에서 자동 계산한다. 정밀 각도 측정이 어려워도 관찰 범주·RULA·구간 판독 가능 여부는 각각 판단한다.

귀의 이주에서 같은 쪽 눈 바깥쪽 끝을 향하는 선과 수평선의 각도를 측정한다. 눈이 수평선보다 위면 양수, 아래면 음수다. `기준 각도 − 작업 각도`는 기준 대비 머리 숙임각 변화이며, 목 관절만의 굽힘각이나 RULA 총점이 아니다. 몸통 움직임도 포함된다.

**버전 2의 구간 규칙:** 기준 모습보다 머리가 분명히 아래로 기울어진 상태가 1초 이상이면 시작, 중립에 가까운 모습으로 1초 이상 복귀하면 종료한다. 눈만 움직인 것은 제외한다. 조건을 확인한 뒤 최초 진입·복귀 시각으로 구간을 기록한다. 시작부터 이미 숙인 상태는 1구간으로 세고 별도로 표시한다. 합계 시간은 각 구간의 시작~종료 합이다. 이는 육안 관찰 규칙이며 특정 각도 이상 노출시간이나 임상 위험 기준이 아니다. 이전 버전 1의 20°/10° 임계값 규칙과 혼합하지 않는다.

각도·횟수·시간은 초기값 없이 빈칸이다. 실제 0은 직접 입력해야 한다. 회전·가려짐 등으로 판독할 수 없는 값은 결측으로 구분한다. 영상 일부가 판독 불가라면 전체 구간 수·시간을 입력하지 않으며 사유를 남긴다. 조건별 결측률 차이도 함께 검토해야 한다. 분석 범위는 각 배치의 **두 번째 시행**이며 세 시행 전체로 일반화하지 않는다.

측정 기록은 같은 브라우저에 버전별로 임시 저장되고 CSV로 다운로드할 수 있다. 사진·영상 파일을 웹사이트로 업로드하거나 자동 분석하지 않는다. 온라인 수신 코드가 관찰 버전 2를 지원할 때만 온라인 전송 버튼이 활성화된다. CSV 다운로드는 독립적으로 사용할 수 있다. 기본 여섯 시행·두 설문의 전송은 기존 방식대로 유지된다.

`sheet-receiver.generated.gs` 전체를 기존 Apps Script 프로젝트에 반영하고 **기존 배포를 새 버전으로 갱신**하면 같은 웹앱 URL로 측정값도 수신한다. `resetResults`는 실행하지 않는다. 기존 탭은 그대로 두고, 최초 실제 측정값 수신 시 `자세 관찰 v2` 탭에 참가자별 A·B 두 행을 추가한다. 제출 번호·참가 번호·시드·실제 두 번째 시행시간을 원본과 검증한다. 같은 관찰 제출의 재전송은 같은 두 행을 갱신한다. 관찰표·단계별 RULA와 원래 평가점수는 JSON 열에 보존한다.

검증: `node build.mjs` 후 `node verify-observation.mjs`. 실제 참가자 자료를 전송하지 않는 계산·저장 모의 검증이다. `observation.html?test=1`은 측정값이 비어 있는 테스트 기록지이며 응답을 전송하지 않는다.

안내 모형 이미지: `assets/posture-guide.png` (내장 이미지 생성 도구). 생성 지시: 같은 인체 모형의 측면 기준 자세와 아래를 보는 작업 자세, 귀·눈 기준점, 고정 휴대폰 촬영 안내. 실제 측정값·각도 숫자를 넣지 않은 교육용 이미지이며 기기 배치도나 측정 근거 사진으로 사용하지 않는다.

실험 규칙 버전 6. 참가자는 화면 안내에 따라 혼자 진행한다. A는 책상 왼쪽 태블릿 원본, B는 노트북 입력창 왼쪽 원본이다. 노트북에는 참가 번호 **A01~A20**을 입력한다. 노트북이 **6자리 숫자 시드**를 자동 생성하며 태블릿에 같은 참가 번호와 시드를 한 번 입력한다. 태블릿은 **X, Y, Z 버튼**으로 원본을 바꾼다.

## 시행과 원본

- 각 배치에서 3회, 총 6회 수행한다. 각 블록에서 X, Y, Z를 한 번씩 쓴다.
- 원본당 **14품목**, 시행당 **8개 입력**, 코드는 **5글자**(영문 3개와 숫자 2개 교대)다. 시행당 제한은 90초다.
- 참가자별 원본 순서는 무작위이며 같은 참가자의 두 블록은 같은 순서를 쓴다.
- 매 시행마다 원본의 품목 순서와 코드를 새로 생성한다. 같은 반복 번호의 A와 B는 목표 8행 위치와 입력칸 순서를 맞춘다.
- 참가 번호와 시드로 재현 가능한 원본을 사용한다. 같은 참가 번호라도 시드를 바꾸면 다른 원본이 생성된다. 태블릿의 각 버튼은 해당 참가자의 A 배치에서 그 원본을 쓰는 시행과 정확히 같은 표를 연다. 버튼을 다시 눌러도 그 표는 유지된다.
- 참가자 20명은 A→B, B→A에 10명씩 사전 무작위 배정된다. 태블릿의 참가 번호와 시드는 노트북 준비 화면의 값과 일치해야 한다.

원본과 코드는 `materials.json`의 세 품목 목록과 `protocol.json`의 설정을 바탕으로 생성한다. 생성 규칙 버전은 4, 목표 행 규칙 버전은 4, 배정 규칙 버전은 3다. 구성 시드를 바꾸면 두 HTML과 수신 스크립트를 함께 다시 생성해야 한다.

## 과업과 자동 기록

입력 대상 확인 → 원본 탐색과 코드 읽기 → 입력 → 원본과 대조를 반복한다. 불일치가 있으면 다시 읽고 수정한다. 여덟 칸을 확인하면 제출하고, 90초가 되면 당시 값으로 종료한다.

`task_log`는 [첫 문자까지 초, 8칸을 처음 각각 5글자로 채운 시점, 이후 종료까지 초, 한 번 5글자를 채운 뒤 수정한 칸 수, 입력칸 재방문 수]이다. 미발생 시간은 `null`이다. 8칸 충족은 정답 판정을 뜻하지 않는다. 첫 입력 지연과 후반 시간에는 여러 행동이 섞이며 입력칸 재방문은 시선 이동 횟수가 아니다.

## 블록 종료 설문

참가자는 세 시행을 마친 직후 원본 읽기 때와 키 입력 때의 고개 자세를 각각 선택하고 목 불편감과 RTLX에 응답한다. 자세 보기는 정면에 가까움, 아래로 숙임, 옆으로 돌림, 숙인 채 옆으로 돌림, 기억이 불확실함이다. 원본 읽기는 품목을 찾거나 코드를 대조하려고 원본을 보는 동안, 키 입력은 키보드로 문자를 적는 동안이다.

RTLX 여섯 항목은 **0~100점, 5점 간격의 슬라이더**다. 각 막대를 움직여야 응답으로 인정하며 선택 전 기본 위치는 점수로 저장하지 않는다. 수행도는 0 매우 잘함~100 매우 못함이다.

## 결과 형식

여섯 시행과 두 설문은 마지막에 한 번에 전송한다. 초기화된 **실험 결과** 탭 하나에 참가자별 6행, 23열을 저장한다. 초기화 전 통합문서 전체는 별도 백업으로 보관한다. 같은 블록 설문은 세 행에 반복되므로 독립된 세 응답으로 세지 않는다.

`submitted_at`, `submission_id`, `participant`, `assignment`, `block`, `repetition`, `condition`, `source_set`, `elapsed_seconds`, `timed_out`, `correct`, `wrong`, `blank`, `posture`, `neck_after`, `rtlx`, `task_log`, `target_rows`, `item_names`, `responses`, `expected_codes`, `seed`, `versions`

- `posture`: [원본 읽기 자세, 키 입력 자세] 응답 문자열.
- `rtlx`: [정신적 요구, 신체적 요구, 시간적 요구, 수행도, 노력, 좌절감, 여섯 점수의 평균]. 평균은 소수 둘째 자리까지 저장한다.
- `versions`: [실험, 코드 생성, 목표 행, 배정] = [6, 4, 4, 3].
- `source_set`: 각 시행에서 사용한 X, Y, Z.
- `target_rows`, `item_names`, `responses`, `expected_codes`: 같은 입력 순서에 대응하는 8개 값.
- `seed`: 노트북에서 자동 생성한 6자리 숫자 문자열. 앞자리 0도 보존하며 참가 번호와 함께 두 기기의 원본을 맞춘다. 원본 선택 문자는 시드에 붙이지 않는다.

앞뒤 공백 제거와 대문자 변환 후 정답, 오답, 빈칸을 판정한다. 시간초과는 90초로 기록한다. 같은 제출 번호의 재전송은 중복 저장하지 않는다. 분석 단위는 참가자이며 원본 읽기 때 숙임 응답을 주 지표로, 키 입력 때 자세와 수행 기록은 별도로 비교한다.

## 사전 점검

`?test=1`로 열면 건너뛰기를 사용할 수 있고 결과를 전송하지 않는다. 실제 참가자는 일반 실험 링크를 쓴다. 참가 번호는 한 번의 본 실험에 한 번만 사용한다.
