# 자료 입력 자세 실험

[노트북 실험](https://kjs1011.github.io/ergo-typing/) / [태블릿 원본](https://kjs1011.github.io/ergo-typing/tablet.html)

## 최악 장면의 머리 기울기 · 관찰 버전 4

기존 여섯 번의 입력과 설문은 유지한다. A·B 각각 두 번째 시행을 촬영하고 입력 시작~제출의 작업 구간에서 가장 심하게 숙인 서로 다른 구간을 최대 세 개 선정한다. 한 번 숙인 채 유지한 장면을 여러 프레임으로 중복 집계하지 않는다. 세 구간이 없으면 있는 것만 기록한다. 이 선택법은 고정 시점 표집이나 대표 자세 표집이 아니라 최악 자세 후보의 관찰이다.

귀 이주에서 같은 쪽 눈 바깥 끝으로 향하는 선과 화면 수평선 사이의 머리 기울기를 측정한다. 눈이 아래면 양수, 위면 음수다. 카메라를 수평·측면에 고정하고 두 조건에서 구도를 유지한다. 고개 회전·가려짐으로 가장 심한 후보의 각도를 잴 수 없으면 측정 불가로 남기고 덜 숙인 장면으로 바꾸지 않는다. 이 값은 목 관절만의 굽힘각·전신 부담·질환 위험 점수가 아니다.

사이트 안에 측정 그림, 정의, 부호 설명과 선택적인 사진·영상 각도 도우미가 있다. 도우미는 파일을 로컬 객체 URL로만 열고, 영상 정지 장면 또는 사진에 귀→눈 두 점을 클릭해 atan2(dy, |dx|) 각도를 계산한다. 원본 파일·얼굴 좌표·파일 이름은 결과 전송이나 CSV에 포함하지 않는다. 각도와 선택적인 영상 시각만 입력한다. 외부 이론 검색이나 평가표 점수 입력은 요구하지 않는다.

각 장면은 measured / unreadable / unused로 구분한다. 0도는 유효한 측정값이고 빈칸을 0으로 바꾸지 않는다. 선택된 장면의 최대와 평균, 유효·측정 불가 수를 저장한다. 이 평균은 전체 작업 평균이 아니다. 가장 심한 후보가 측정 불가인 조건은 남은 값만으로 실제 최악각을 확정하지 않는다. 조건별 선정 수·측정 불가, 작업시간 차이를 함께 보고한다.

관찰 버전 3의 고정 시점 자세 비율·RULA·횟수와 혼합하지 않는다. 버전 4에서는 각도만 기록한다. 실제 작업 영상은 참가자가 보관하며 업로드하지 않는다. 사진·영상 도우미는 선택 사항이고 직접 잰 각도도 입력할 수 있다.

건너뛴 진행은 검토용이며 실제 결과로 전송하지 않는다. CSV에는 review_only를 남긴다. 관찰값은 임시 저장·CSV 다운로드가 가능하고 수신 코드가 버전 4일 때만 온라인 전송 버튼이 보인다. 기존 탭을 지우지 않고 자세 관찰 v4 탭을 사용한다. resetResults는 실행하지 않는다.

번호·시드는 내부 기록과 원본 재현에 유지하되, 참가 번호는 처음 한 번, 연결번호는 태블릿 연결 시 한 번만 간단히 표시한다. 별도 설명 페이지·안내음·카운트다운은 없다.

방법 근거: Kramer & Bauer (2023), Analysis of Adolescents’ Head to Shoulder Region during Tablet Use from Sagittal and Frontal RGB Images, https://doi.org/10.3390/applbiosci2030027 ; Kinovea 각도 측정의 2차원 평면 조건, https://www.kinovea.org/help/en/measurement/angle.html . 이 링크는 제작 근거이며 참가자가 방문할 필요는 없다.

실험 규칙 버전 6. 참가자는 화면 안내에 따라 혼자 진행한다. A는 책상 왼쪽 태블릿 원본, B는 노트북 입력창 왼쪽 원본이다. 노트북에는 참가 번호 **A01~A20**을 입력한다. 노트북이 **6자리 숫자 시드**를 자동 생성하며 태블릿에 같은 참가 번호와 시드를 한 번 입력한다. 태블릿은 **X, Y, Z 버튼**으로 원본을 바꾼다.

## 시행과 원본

- 각 배치에서 3회, 총 6회 수행한다. 각 블록에서 X, Y, Z를 한 번씩 쓴다.
- 원본당 **14품목**, 시행당 **8개 입력**, 코드는 **5글자**(영문 3개와 숫자 2개 교대)다. 시행당 제한은 90초다.
- 참가자별 원본 순서는 무작위이며 같은 참가자의 두 블록은 같은 순서를 쓴다.
- 매 시행마다 원본의 품목 순서와 코드를 새로 생성한다. 같은 반복 번호의 A와 B는 목표 8행 위치와 입력칸 순서를 맞춘다.
- 참가 번호와 시드로 재현 가능한 원본을 사용한다. 같은 참가 번호라도 시드를 바꾸면 다른 원본이 생성된다. 태블릿의 각 버튼은 해당 참가자의 A 배치에서 그 원본을 쓰는 시행과 정확히 같은 표를 연다. 버튼을 다시 눌러도 그 표는 유지된다.
- 참가자 20명은 A→B, B→A에 10명씩 사전 무작위 배정된다. 태블릿의 참가 번호와 시드는 노트북 준비 화면의 값과 일치해야 한다.

원본과 코드는 `materials.json`의 세 품목 목록과 `protocol.json`의 설정을 바탕으로 생성한다. 생성 규칙 버전은 4, 목표 행 규칙 버전은 4, 배정 규칙 버전은 3다. 구성 시드를 바꾸면 두 HTML과 수신 스크립트를 함께 다시 생성해야 한다.

## 과업과 자동 기록

입력 대상 확인 → 원본 탐색과 코드 읽기 → 입력 → 원본과 대조를 반복한다. 불일치가 있으면 다시 읽고 수정한다. 여덟 칸을 확인하면 제출하고, 90초가 되면 당시 값으로 종료한다.

`task_log`는 [첫 문자까지 초, 8칸을 처음 각각 5글자로 채운 시점, 이후 종료까지 초, 한 번 5글자를 채운 뒤 수정한 칸 수, 입력칸 재방문 수]이다. 미발생 시간은 `null`이다. 8칸 충족은 정답 판정을 뜻하지 않는다. 첫 입력 지연과 후반 시간에는 여러 행동이 섞이며 입력칸 재방문은 시선 이동 횟수가 아니다.

## 블록 종료 설문

참가자는 세 시행을 마친 직후 원본 읽기 때와 키 입력 때의 고개 자세를 각각 선택하고 목 불편감과 RTLX에 응답한다. 자세 보기는 정면에 가까움, 아래로 숙임, 옆으로 돌림, 숙인 채 옆으로 돌림, 기억이 불확실함이다. 원본 읽기는 품목을 찾거나 코드를 대조하려고 원본을 보는 동안, 키 입력은 키보드로 문자를 적는 동안이다.

RTLX 여섯 항목은 **0~100점, 5점 간격의 슬라이더**다. 각 막대를 움직여야 응답으로 인정하며 선택 전 기본 위치는 점수로 저장하지 않는다. 수행도는 0 매우 잘함~100 매우 못함이다.

## 결과 형식

여섯 시행과 두 설문은 마지막에 한 번에 전송한다. 초기화된 **실험 결과** 탭 하나에 참가자별 6행, 23열을 저장한다. 초기화 전 통합문서 전체는 별도 백업으로 보관한다. 같은 블록 설문은 세 행에 반복되므로 독립된 세 응답으로 세지 않는다.

`submitted_at`, `submission_id`, `participant`, `assignment`, `block`, `repetition`, `condition`, `source_set`, `elapsed_seconds`, `timed_out`, `correct`, `wrong`, `blank`, `posture`, `neck_after`, `rtlx`, `task_log`, `target_rows`, `item_names`, `responses`, `expected_codes`, `seed`, `versions`

- `posture`: [원본 읽기 자세, 키 입력 자세] 응답 문자열.
- `rtlx`: [정신적 요구, 신체적 요구, 시간적 요구, 수행도, 노력, 좌절감, 여섯 점수의 평균]. 평균은 소수 둘째 자리까지 저장한다.
- `versions`: [실험, 코드 생성, 목표 행, 배정] = [6, 4, 4, 3].
- `source_set`: 각 시행에서 사용한 X, Y, Z.
- `target_rows`, `item_names`, `responses`, `expected_codes`: 같은 입력 순서에 대응하는 8개 값.
- `seed`: 노트북에서 자동 생성한 6자리 숫자 문자열. 앞자리 0도 보존하며 참가 번호와 함께 두 기기의 원본을 맞춘다. 원본 선택 문자는 시드에 붙이지 않는다.

앞뒤 공백 제거와 대문자 변환 후 정답, 오답, 빈칸을 판정한다. 시간초과는 90초로 기록한다. 같은 제출 번호의 재전송은 중복 저장하지 않는다. 분석 단위는 참가자이며 원본 읽기 때 숙임 응답을 주 지표로, 키 입력 때 자세와 수행 기록은 별도로 비교한다.

## 사전 점검

`?test=1`로 열면 건너뛰기를 사용할 수 있고 결과를 전송하지 않는다. 실제 참가자는 일반 실험 링크를 쓴다. 참가 번호는 한 번의 본 실험에 한 번만 사용한다.
